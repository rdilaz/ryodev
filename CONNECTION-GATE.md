## Unresolved Prerequisites

1. **Separate authorization and exact eligibility.** The user must select an
   already-existing session on a verified laptop, outside the active RyoMap repair.
   Establish exact machine, runtime owner/version/instance, session, project and
   worktree binding using a supported existing surface. No port scanning, raw
   stores, secret discovery, starting, moving, replacing, resuming or restarting
   work to manufacture eligibility. If no eligible surface exists, stop.
2. **Concrete read contract.** Review the installed-version schemas, bounded
   time/size, exact methods and field allowlist for the proposed existing owner's
   `GET /global/health`, `GET /session/:id`, `GET /session/status` subset. Explicitly
   accept or reject the broader all-session upstream status scope; locally retain
   only the enrolled session. Prove no bootstrap, writes, provider traffic or
   lifecycle/model activity attributable to capture. No account/billing calls.
3. **Identity and clock proof.** Verify machine clock accuracy, ownership before
   and after the state read, source identity/sequence and trusted snapshot binding.
   Record source, state-observation and receipt times separately. Establish
   re-verification after restart, rejection of replay/conflict, and revocation.
   If a status is not bound to a turn, omit turn identity and turn-level claims.
4. **Already-approved delivery/access.** Name an existing user-controlled private
   transfer route, its readers, phone viewer origin and cache policy. No such
   route is proven here. Loopback is not phone delivery. Never expose the agent API
   to the phone. New hosting, credentials, grants, infrastructure or tunnels need
   separate review, not an implicit implementation step.
5. **Sanitization, integrity and retention.** Agree the one-session, proposed
   32 KiB cap; reject extra records, unknown schema/fields, wrong identity and
   oversized data. Export only safe aliases, opaque IDs, status, provenance, time,
   version and sequence. Drop other sessions, paths, titles/previews, bodies, raw
   errors, configuration and secrets. Distinguish user-attested provenance from
   authentication; a checksum does not establish the sender. Set memory-only
   retention until deliberate replacement/page close, bounded safe failures and
   explicit forget. Keep demo and real views/stores entirely separate.
6. **Deliberate capture and acceptance evidence.** Only after the contract and
   authorization, permit one foreground sanitized snapshot, then stop. Compare
   two separately authorized, deliberate captures as existing work changes
   naturally, against the owning tool's visible state. Prove non-interference,
   failure preservation, 60s/61s freshness, idle-to-unknown, correct attribution
   gaps, replay rejection and forget behavior. Missing account/model/tests/usage
   remains unavailable; richer demo waits/completions are not assumed supported.

Until these facts are established, **real connection remains unaccepted**. No
eligible machine, session, endpoint or transfer route has been fabricated.
Continuous observation, notifications, provider allowances, remote controls,
approval actions, RyoMap integration, merges and deployments remain out of scope.
